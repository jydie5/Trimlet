# Trimlet Mac 操作改善プラン — 2026-08-26

- Status: Planned; no implementation in this change
- Target: 次回Macヒューマンチェック
- Shared consideration: 色の意味、ショートカット、状態遷移、受け入れ条件はWindows版とも共有し、描画と再生制御だけを各OSで実装する。

## 1. 作成中の選択範囲を塗る — TRIM-022

### 問題

IN点の緑線とOUT点の赤線は見えるが、両方を決めた後も作成中の範囲は点線だけである。追加済み範囲は青で塗られるため、「いま作っている範囲」と「既にシーケンスに入った範囲」の状態差が弱い。

### 推奨する表示

| 状態 | 表示 |
|---|---|
| INのみ設定 | 緑のIN線。面はまだ塗らない |
| IN／OUT設定済み・未追加 | 半透明の紫系の面＋現在の点線枠 |
| シーケンスへ追加済み | 青の面 |
| 選択中の追加済みクリップ | 濃い青の面 |
| Fast候補／キーフレーム | 現状どおりオレンジの輪郭／目盛り |
| 再生位置 | 白いプレイヘッド |

紫は青・緑・赤・オレンジと役割が重なりにくい暫定案とする。実装前にmacOSのライト／ダーク両方でコントラストを確認する。色覚差に備え、作成中は点線、追加済みは塗りのみという形の差と、短い凡例も残す。

### 状態遷移

1. INとOUTが有効になった時点で紫の範囲を表示する。
2. 「シーケンスへ追加」が成功した時点で紫を消し、同じ位置に青の追加済み範囲を表示する。
3. 追加が重複等で失敗した場合は紫を維持し、ユーザーが修正できるようにする。
4. 「トリム編集」中も変更案を紫で重ね、現在保存されている青い範囲との差を判別できるようにする。適用またはキャンセル時の挙動を実装前に確定する。

### 実装タスク

1. Mac／Windows共通の色と線種の意味を仕様へ追加する。
2. Macのソースタイムラインにドラフト面を追加し、既存範囲・Fast候補・キーフレームとの描画順を固定する。
3. 重複、極短範囲、画面端、長尺動画で視認性を確認する。
4. ライト／ダークとアクセントカラー変更時のスクリーンショットを比較する。

### 受け入れ条件

- IN／OUT設定直後、未追加範囲を青い追加済み範囲と一目で区別できる。
- 追加成功後、同じ範囲が紫から青へ変わり、ドラフト表示は残らない。
- 線種と凡例により、色を判別しにくい場合も状態が分かる。
- 選択中、Fast候補、キーフレーム、プレイヘッドを同時表示しても意味が衝突しない。

## 2. 動画読込後の全面パネルをなくす — TRIM-023

### 現状の見立て

現行Macコードには、通常の動画ドロップを承認させる確認ダイアログはない。一方、読込直後に自動開始するキーフレーム解析が共通の処理パネルを全面表示する。この画面が今回指摘された「確認ダイアログ」である可能性が高いため、実装前に同じ入力で再現して画面名を確定する。

### 推奨する挙動

- MP4／MOV読込後は映像と基本操作をすぐ使える状態にする。
- キーフレーム解析は背景で継続し、ソースタイムライン内にスピナーと「キーフレーム解析中…」を表示する。
- 完了時はパネルを出さず、目盛りと検出数をその場で更新する。
- 失敗時はFast機能の近くへ非モーダルな警告を出し、通常再生とAccurate編集は妨げない。
- 長時間かかりキャンセルが必要なプロキシ生成と書き出しは、現在の処理パネルを維持する。
- 編集済みシーケンスを破棄して別動画へ置き換える場合の確認は、安全性の別要件として削除対象に含めない。

### 実装タスク

1. 指摘された入力形式で再現し、全面表示の処理種別を記録する。
2. キーフレーム解析だけを非モーダル表示へ分離する。
3. 解析中も再生、停止、シーク、IN／OUT設定が動くことを保証する。
4. 完了、失敗、キャンセル、別動画への切替時の状態破棄を試験する。

### 受け入れ条件

- 通常動画をドロップしても、承認や「閉じる」を要求する全面パネルが出ない。
- 解析の開始・実行中・完了・失敗はタイムラインから確認できる。
- 解析中に編集操作を始めても、解析完了時に再生位置やIN／OUTが変わらない。
- M2TSのプロキシ生成とMP4書き出しでは、進捗とキャンセルが引き続き見える。

## 3. 映像を見ながら高速に前後移動する — TRIM-024

### 採用候補

第一段階はJ・K・Lの「シャトル」、第二段階は現在のスライダーを高速スクラブ向けに改善する。これはPremiere ProとFinal Cut Proの両方で使われる慣習的な操作であり、画面意匠や文言はコピーせず、Trimlet独自の小さな操作案内として実装する。

#### A. J・K・Lシャトル

- `J`: 逆方向へ再生。繰り返し押すと 1x → 2x → 4x → 8x。
- `K`: 停止。
- `L`: 順方向へ再生。繰り返し押すと 1x → 2x → 4x → 8x。
- 反対方向のキーを押すと減速し、その後に方向を反転する。
- `K+J`／`K+L`: 低速移動。短く押した場合の1フレーム移動も候補とし、既存の左右キーと衝突しないことを先に試作検証する。
- 画面には `J 逆再生　K 停止　L 再生` と現在速度を小さく表示し、ショートカットを知らない人にも発見可能にする。

AVPlayerが原本形式で安定した逆再生・高速再生を行えない場合は、対応能力を確認して速度上限を下げるか、プレビュー用プロキシ／連続シークへフォールバックする。非対応のままボタンだけ反応して見える状態にはしない。

#### B. 高速スクラブ

- スライダーを掴んでいる間は、連続要求をまとめ、再生に適した許容幅付きシークで映像を追従させる。
- 指を離した時点で、現在と同じ許容誤差ゼロの正確な位置へ確定する。
- 高速ドラッグ中は音声を鳴らさず、映像探索を優先する。
- IN／OUT、選択範囲、追加済みクリップの表示はドラッグ中も維持する。

#### 今回は保留するもの

Final Cut Pro型のホバースキマーは有力だが、現在の28pxの細いソースバーでは誤操作が増える。フィルムストリップ、ズーム、パンを扱うTRIM-014の設計時に、再生位置とは別の一時プレビューカーソルとして検討する。

### 実装タスク

1. MP4／MOV／M2TSプロキシで順・逆方向と各速度のAVPlayer対応能力を測る。
2. シャトルの状態機械（方向、速度、停止、終端、既存プレビューの解除）をMac／Windows共通仕様にする。
3. MacでJ・K・Lと速度表示を実装し、テキスト入力中には発火させない。
4. スライダーのドラッグ中／確定時を分け、要求の間引きと最終正確シークを実装する。
5. Windows担当向けに同じ操作とフォールバック要件をhandoverへ追記する。

### 受け入れ条件

- J、K、Lだけで映像を見ながら前後へ移動し、停止位置からIN／OUTを設定できる。
- キー連打による速度変更が画面表示と一致し、先頭／終端で暴走しない。
- 5分以上の長尺・長GOP動画でも、スライダーを左右へ振ったとき映像更新が操作に追従する。
- スライダーを離した後の時刻表示と実際のフレームが一致する。
- 再生、シーケンスプレビュー、1／10フレーム移動、5秒移動を劣化させない。
- MacとWindowsでJ・K・Lの意味が同じになる。

## 実施順

1. TRIM-022でドラフトと追加済みの視覚状態を分ける。
2. TRIM-023で読込直後の不要な全面表示を非モーダル化する。
3. TRIM-024AのJ・K・Lシャトルを実装し、短いヒューマンチェックを行う。
4. TRIM-024Bの高速スクラブを実装し、長尺素材でヒューマンチェックを行う。

3点を一度に実装して評価不能にせず、各段階で操作の意味と回帰を確認する。ただし次回配布物では3点をまとめて確認できる状態を目標にする。
