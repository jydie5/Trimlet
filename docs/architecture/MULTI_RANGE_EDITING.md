# Multi-range editing design

- Status: Accepted for Mac milestone 0.3
- Updated: 2026-08-24

## Model boundary

`TrimletCore` owns platform-neutral editing meaning:

- `MediaTimestamp`: integer value plus integer timescale, convertible to display/playback seconds.
- `EditSegment`: stable identifier plus inclusive IN and exclusive OUT timestamps.
- `EditList`: explicit output order, validation, total duration, overlap detection, and immutable-style mutations.
- `MultiRangeExportPlan`: ordered FFmpeg stages and temporary-file requirements for Accurate and Fast modes.

SwiftUI and AVFoundation use seconds only at their adapter boundary. The retained edit list never uses a frame number or floating-point seconds as its stored truth.

## Controller state

The Mac controller keeps:

- one mutable draft `TrimRange` for the current IN/OUT controls;
- one canonical `EditList` for retained output segments;
- an optional selected segment identifier;
- undo and redo stacks containing prior edit-list snapshots;
- an optional preview sequence cursor;
- inspected audio streams and the selected absolute FFmpeg stream index.

Opening a new source resets all of this state. Loading a segment into the draft does not mutate the edit list until Update is chosen.

## Preview state machine

Single-segment preview seeks to its IN timestamp and stops at its exclusive OUT timestamp.

Sequence preview follows edit-list order. On reaching one OUT boundary it pauses, seeks to the next segment IN with zero tolerance, resumes, and stops after the final OUT. Manual play, seek, source change, edit mutation, or export cancels sequence preview.

## Export stages

Every multi-range export writes generated temporary segment files under one operation directory. A final concat-demuxer stage produces the incomplete destination. Only a validated output is moved to the user-selected path. Cancellation or failure removes the operation directory and incomplete destination.

Temporary paths are generated by Trimlet and therefore can be safely represented in the concat list after single-quote escaping. Source and destination paths still travel only through `Process.arguments`; no shell command is constructed.

Progress is weighted by retained source duration across segment stages. The final concat stage is reported separately and never decreases displayed progress.

## UI composition

The existing media-first layout remains. Below playback controls:

1. a compact overview timeline renders every retained segment;
2. draft IN/OUT controls add or update a segment;
3. a horizontally compact edit-list row exposes selection, duration, reorder, and delete;
4. preview-all and total-duration controls appear only when at least one retained segment exists;
5. audio selection appears only when the source has multiple audio streams.

No permanent tutorial paragraph is added to the work surface.
