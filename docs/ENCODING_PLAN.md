# 正確モードのFFmpeg・エンコード設計

- Status: PoC実装済み／製品版設計は未完了
- Updated: 2026-08-16

## 1. 現時点の結論

PoCでは、指定範囲を再エンコードしてMP4へ出力する流れと、MacのVideoToolboxハードウェアエンコーダーが実際に利用できることを確認した。

ただし、現在の引数はCFRのH.264テスト動画と代表的なM2TSで基本動作を確認するための暫定値である。画質、HDR、インターレース、VFR、PTS不連続、音声境界などを含めた製品版のエンコード方針は未完成であり、現状を最終仕様として扱わない。

## 2. PoCで使用している正確モード

概念的なコマンドは次のとおり。

```bash
ffmpeg -hide_banner -loglevel error -nostats -y \
  -i INPUT \
  -ss START \
  -t DURATION \
  -map 0:v:0 \
  -map 0:a:0? \
  -c:v h264_videotoolbox \
  -b:v 12M \
  -c:a aac \
  -b:a 256k \
  -movflags +faststart \
  OUTPUT.mp4
```

実装は`apps/macos/Sources/TrimletCore/FFmpegExportPlan.swift`にある。

### 現在の判断理由

- `-ss`を`-i`の後に置く。
  - 入力前の高速シークだけに依存せず、目的位置までデコードしてから出力を始める。
  - 長いGOPやM2TSで、入力前シークによって映像ストリームが出力されないケースを実測したため。
- `-t`にはOUT-INの選択時間を渡す。
- 映像は`h264_videotoolbox`を使用する。
- 音声はMP4との互換性を優先してAACへ変換する。
- `-movflags +faststart`でMP4のメタデータを先頭側へ移動する。
- パスはシェル文字列へ展開せず、プロセスの引数配列として渡す。

## 3. 実測結果

Apple Silicon Mac上で、1秒間隔のキーフレームを持つH.264/AC-3 M2TSから1.5秒〜4.0秒を指定した。

| モード | 出力 | 実測時間 | 結果 |
|---|---|---:|---|
| 高速 | H.264/AAC MP4 | 2.571667秒 | キーフレーム差を含め成功 |
| 正確 | H.264/AAC MP4 | 2.500000秒 | 指定時間どおり成功 |

正確モードの出力はH.264 High Profile、`yuv420p`、30 fpsとして生成された。ただしProfileやピクセル形式は現在明示指定しておらず、エンコーダーが選んだ結果である。

## 4. FFmpegバージョン

PoCの検証記録で使用したバージョンはFFmpeg 7.1.1である。これは再現記録であり、製品版の採用バージョン指定ではない。開発機のHomebrew構成や「最新版」を暗黙の配布基準にしない。

正式なバイナリ配布・再現可能なテストを始める前に、次を行う。

1. FFmpeg公式配布情報を再確認し、採用する正確な版とソースコミットを固定する。
2. MacとWindowsで可能な限り同じメジャーバージョンと構成方針を使う。
3. FFmpegのビルド設定、ライセンス、同梱方式、ソース入手方法を記録する。
4. バージョン差によるMPEG-TS、VideoToolbox、タイムスタンプ処理の回帰試験を行う。

初回GitHub公開はソースのみとし、FFmpeg/ffprobeを同梱しない。PoCで使用中のHomebrew版はGPL機能を含むため、その実行ファイルを配布物へコピーしない。

参考: [FFmpeg公式ダウンロード](https://ffmpeg.org/download.html)

## 5. ハードウェア支援の現状

ローカルFFmpegは`--enable-videotoolbox`でビルドされ、次のエンコーダーを利用できる。

- `h264_videotoolbox`
- `hevc_videotoolbox`
- `prores_videotoolbox`

PoCの正確モードは`h264_videotoolbox`を明示指定する。ローカル環境ではソフトウェアエンコードを許す`allow_sw`の既定値がfalseであり、その状態で書き出しに成功した。このため、PoCの正確モードではApple SiliconのVideoToolboxハードウェアエンコードが実際に使われている。

一方、現在は`-hwaccel videotoolbox`を指定していない。したがって、明示的に保証できるのはエンコード支援であり、FFmpeg側の入力デコードは製品版で別途検証する。

## 6. 製品版までに解決する項目

### 6.1 フレーム境界とタイムスタンプ

- IN/OUTを`Double`秒ではなく、整数PTSとtimescaleで保持する。
- UIのフレーム番号ではなく、原本の実PTSを編集境界の正本とする。
- 29.97/59.94 fps、VFR、Bフレーム、長いGOPで境界を検証する。
- M2TSの開始PTS、PTS/DTS不連続、破損GOPに対する補正方針を決める。
- 必要に応じて映像の`trim/setpts`と音声の`atrim/asetpts`を使用する。
- OUT境界を包含／非包含のどちらとして扱うかを共通仕様として固定する。
- AACエンコーダーディレイを含む音声境界とA/V同期を測定する。

### 6.2 画質とビットレート

- 固定12 Mbpsを廃止し、解像度、フレームレート、入力品質、用途に応じて決定する。
- 品質優先、標準、容量優先などの少数のプリセットを検討する。
- VideoToolboxの品質指定とビットレート指定を比較する。
- 速度と圧縮効率について、VideoToolboxとソフトウェアエンコーダーを比較する。
- Profile、Level、参照フレーム、GOP長、レート制御を必要に応じて明示する。

### 6.3 ピクセル形式、HDR、色

- 8-bit SDRと10-bit/HDRをffprobeで判定する。
- H.264へ落とすべきでない入力ではHEVC Main 10等を提案する。
- `pix_fmt`を入力と出力方針に応じて明示する。
- color primaries、transfer、matrix、rangeを維持または正しく変換する。
- HDRからSDRへ変換する場合は、暗黙変換せず明示的なトーンマッピング方針を用意する。
- 回転、SAR/DARなどの表示メタデータを検証する。

### 6.4 インターレース

- ffprobeのfield order等からインターレースを判定する。
- 維持、自動デインターレース、ユーザー選択のどれを採用するか決める。
- デインターレース方式と出力フレームレートを実写1080iで比較する。
- フィルターを使用した場合もハードウェアエンコードへ正しく接続できるか確認する。

### 6.5 音声、字幕、メタデータ

- 複数音声からの選択を可能にする。
- チャンネルレイアウト、サンプルレート、言語タグを維持する。
- AACビットレートをチャンネル数に応じて決定する。
- 字幕、チャプター、番組情報を保持／除外する方針を明示する。
- `map_metadata`や`map_chapters`を入力ごとに計画する。

### 6.6 ハードウェアデコードとフォールバック

- `-hwaccel videotoolbox`の有無で速度、CPU、メモリ、互換性を比較する。
- ハードウェアデコードからVideoToolboxエンコードまでのデータ転送コストを測定する。
- 対応外入力やVideoToolbox失敗時のソフトウェアフォールバックを、黙って行うかユーザーに提示するか決める。
- ハードウェア使用状況を診断ログで確認できるようにする。

### 6.7 出力の安全性

- 最終出力パスへ直接書かず、一時ファイルへ出力して成功後に確定する。
- FFmpeg終了コードだけでなく、ffprobeで映像・音声ストリームと再生時間を検証する。
- キャンセル／失敗した出力が完成品に見えないようにする。
- 空き容量を事前に見積もる。

## 7. 入力解析から引数を決める流れ

製品版では固定コマンドを使わず、次の順序でExportPlanを生成する。

1. ffprobeでコンテナ、全ストリーム、PTS、フレームレート、GOP、field order、ピクセル形式、色、音声を解析する。
2. 選択範囲を原本PTSへ変換する。
3. Fastで安全にコピーできるか判定する。
4. Accurateの場合、デインターレース、色変換、コーデック、品質、ハードウェア利用を決める。
5. 映像、音声、字幕、メタデータのmapを明示する。
6. 一時出力へ書き出す。
7. ffprobeと再生試験で境界、ストリーム、A/V同期を検証する。
8. 成功時だけ最終ファイル名へ確定する。

## 8. MacとWindowsの分担

共通にするもの:

- PTS基準のIN/OUT意味
- Fast/Accurateのユーザー向け意味
- 出力コンテナと標準コーデック
- ffprobe解析項目
- 品質プリセットの意味
- 出力後検証と安全性
- 共通テストメディアと許容誤差

Mac固有:

- VideoToolboxのH.264/HEVC/ProRes選択
- VideoToolboxハードウェアデコード
- Apple Silicon上の速度、消費電力、品質評価

Windows固有のハードウェアエンコーダーはWindows担当が選定するが、ユーザーに見える品質プリセットと境界仕様は本書および`PLATFORM_CONTRACT.md`に合わせる。

## 9. 実施順序

ヒューマンチェック後の推奨順序:

1. FFmpegを採用版へ更新・固定する。
2. ffprobeの型付き解析モデルを作る。
3. IN/OUTを整数PTSへ移行する。
4. CFR、29.97/59.94、VFR、長いGOP、M2TSで境界試験を自動化する。
5. SDR向け品質プリセットを決める。
6. インターレース対応を決める。
7. HDR/10-bit対応を決める。
8. 音声・メタデータ・複数ストリームを整える。
9. ハードウェアデコードを比較導入する。
10. 一時出力、出力後検証、容量見積もりを完成させる。
