## Mac実画面確認（2026-09-08）

Trimlet 0.4開発版の空の画面を確認し、既存の合成動画`TestMedia/trimlet-sample.mp4`（8秒）をOpenダイアログから読み込んだ。0秒でIN、5秒移動、OUT、追加、カード選択、トリム開始、新規作成へ戻る、シーケンス再生、停止を実行。AX状態とスクリーンショットで結果を確認した。アプリコードは変更していない。

- **P0・再現済み:** 同じウインドウで追加前→1クリップ追加→カード選択の順に下部領域が増え、映像領域が大幅に縮む。取得画像（1108×768）の映像領域は概ね257→116→87画像ピクセル高となった。これはスクリーンショット上の概算であり、OSの論理サイズ測定ではない。映像領域の下限と領域配分の改善を最優先にする。
- **P1・再現済み:** 動画読込直後と追加後、IN/OUT未設定なのに「この範囲は正確モードを推奨」が表示される。有効な範囲の判定前には出さない。

## 目指す操作体験

元動画から範囲を選び、編集シーケンスへ追加し、並べて完成形を確認する。この二つの時間軸を区別する。既存の「IN → OUT → シーケンスへ追加」、紫の作成範囲、青の追加済み範囲、名前とサムネイル、明示的なトリム編集は維持する。

| 優先 | 改善 | 現在の根拠 | 提案する到達点 |
|---|---|---|---|
| P0 | 表示領域と操作の階層 | 画面下に操作群を縦積み、最小サイズ1000×800、選択時に行が増える | 映像と編集領域の高さを調整可能にし、選択しても再生・追加・書き出し位置が大きく動かない |
| P0 | 新規作成と既存トリムの区別 | 選択ID、トリムID、ドラフトが別々に存在 | 「新規サブクリップ」「○○をトリム」を明示。トリムの適用・取消を対にする |
| P0 | ソースと完成形の区別 | シーケンス再生も同じ映像・ソース時刻を使用 | 再生対象、現在のクリップ、ソース時刻／シーケンス時刻を明示。まず連続したクリップ並びを維持 |
| P1 | タイムラインの直接操作 | 範囲表示と再生位置スライダーが別部品 | 同じ軸上でシークできるタイムラインへ統合。ズーム・表示範囲移動、IN/OUT端のドラッグを段階追加 |
| P1 | 選択クリップの操作 | 改名欄と横並びの操作ボタンが追加表示される | 安定した選択詳細領域に名前・IN/OUT・長さ・トリム操作を配置。並べ替えは挿入位置を示す |
| P1 | 保存と書き出し | プロジェクトメニューと書き出し設定が離れ、処理結果は全面オーバーレイ | 保存は編集内容、書き出しはMP4と明記。書き出し進捗・結果は固定領域に置き、終了確認は必要時に提示 |
| P1 | ヒントと読みやすさ | caption/caption2、常設の説明、複数の再生ボタン | I/O、J/K/Lは意味付きで維持。補助説明はヘルプへ。無効操作は理由を表示。色以外に枠・ラベルも使用 |

レイアウト案は上部にプロジェクト名・保存・書き出し、中央に映像、映像直下に再生操作とソースタイムライン、下部に範囲作成と編集シーケンスを置く。クリップ詳細は十分な幅ではサイド領域、狭い幅では下部の固定領域とし、文字縮小だけで収めない。

## リファクタリングの順序

1. **現行作業を基準化する。** 未コミットの0.4変更を保全し、保存・終了取消・復元・再リンクの確認状態を記録する。内部変更は進められるが、未確認を合格扱いして公開しない。
2. **見た目を変えず責務を分離する。** 画面をWorkspace、Transport、SourceTimeline、RangeEditor、Sequence、ClipInspectorへ分割する。プロジェクトの開閉・保存確認は専用Coordinatorへ移す。単に同じ巨大Controllerを全Viewで監視する分割に留めない。
3. **状態とコマンドを整理する。** 編集セッションを編集内容・選択・新規/トリム状態・Undoへ限定。PlaybackSession、ProjectCoordinator、ExportService、MediaPreparationServiceへ外部処理を分離。再生位置の高頻度更新が全編集UIを無用に更新しない観測境界を設ける。
   キーボード・画面ボタン・macOSメニューを同じコマンドへ接続し、文字入力中のフォーカス制御を統一する。単一の`statusMessage`に操作説明・解析状態・エラーを詰め込まず、操作ごとの実行可否と理由を保持する。例えば高速書き出し不可なら、該当クリップと「正確モードへ変更」の導線を示す。
4. **最初のUI改善を実装する。** 領域サイズ調整、安定した詳細欄、作成/トリム表示、再生対象表示、保存/書き出し導線までを一つの人手確認単位にする。
5. **タイムラインを改善する。** 表示とシークの統合後にズーム・移動、端ドラッグを追加。ドラッグ中は仮表示、確定時に一回のUndoとして記録する。二本指シークの既存挙動を勝手にパンへ変更しない。
6. **確認後に公開・引き継ぎ。** 日英README、新画面画像、変更履歴、Windows向け操作差分と受入条件を更新してコミット・main・リリースへ進む。

AppKit/AVFoundationやFFmpeg処理をCoreへ押し込まず、Coreは編集状態・時間座標変換・入力妥当性を担当する。保存フォーマットやエンコード条件はUI整理と同時に変更しない。

## 次のヒューマンチェック

- 1280×800と1440×900で3クリップ作成・選択・改名しても主要操作が隠れない。明暗テーマとも状態を判別できる。
- 初見でIN → OUT → 追加を完了でき、選択しただけで既存クリップが更新されない。
- トリム取消で元のクリップに戻り、適用・並べ替え・削除をUndo/Redoできる。
- どの再生操作でも「元動画／編集シーケンス」のどちらを再生しているか分かる。
- 二本指シーク、I/O、J/K/Lが使え、名前入力中は編集ショートカットが発火しない。
- 保存・再起動復元・再リンク・終了取消を確認する。
- 長めの書き出しで進捗とキャンセルが分かり、失敗・取消を成功と誤認しない。

コード検証は状態遷移、Undo単位、保存内容不変性、シーク座標変換に集中する。既存のCore/共有契約/生成動画の書き出し検証を回帰確認に用い、見た目の合否は画面確認で判断する。

## 別の設計として残すもの

複数素材、空白・重なりを含む自由配置、複数トラックは後続の編集モデル変更として扱う。これらはプレビュー・書き出し・保存形式への影響が大きい。MacのVFR実フレーム移動はWindowsとの差として別タスク化し、現在のnominal fps方式を実フレーム正確と表示しない。

今回の推奨着手点は責務分離と最初のUI改善。専用タイムラインや新しい編集モデルまで一括で作り直さず、動く比較対象を残しながら進める。

## Build 10：ソースタイムラインの再設計（2026-09-09）

### 目的

Build 9では再生カーソルとIN／OUTのつまみが別の高さに分かれ、どの操作が
再生位置を動かすのか、境界を動かすのかが画面から読み取りにくかった。
特にINを設定した直後にカーソルを動かしたつもりでもINを再取得してしまい、
OUT設定が拒否される経路があった。Build 10では「上で探す、下で範囲を
調整する」という一つの時間軸のモデルに戻す。

### 到達デザイン

- 全体84 pt。上段`0–38 pt`は目盛り・キーフレーム・白い下向き三角と縦線の
  再生ヘッド、下段`40–72 pt`は一つのIN／OUT範囲。左右24 ptは端の操作余白
  として確保し、時間座標には含めない。
- 範囲は実際の時刻位置に描き、短い範囲でも見た目だけの最小幅を作らない。
  下書きは紫＋点線、追加済みは青。INは緑、OUTは赤で、線種・ラベルも併用する。
- INは`[xIN−24,xIN)`、OUTは`[xOUT,xOUT+24)`の同じ高さの外向きグリップ。
  判定区間は重ならず、端でも余白内に置ける。
- ポインターダウンで対象を固定する。グリップ以外のクリック／ドラッグは
  再生位置だけをシークする。境界ドラッグはつかんだ時の差分を保ち、境界
  だけを動かす。範囲全体をずらすスリップ操作は導入しない。
- I／Oと画面ボタンは現在位置を設定するだけで、再生を要求しない。二本指
  シークは維持する。ホバー／ドラッグ中は対象名と時刻を示す。

### 検証単位

Build 10の自動テスト、Mac開発版のビルド、署名・実行ファイル確認、共有契約、
および本番描画コンポーネントのオフスクリーン確認（通常／短い範囲／INのみ／
