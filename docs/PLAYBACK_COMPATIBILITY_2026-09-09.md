# Mac再生互換性修正（0.4開発版・ビルド8）

## 問題と原因

ユーザー指定のローカルMP4を調査したところ、映像VP9（720×480）／音声Opus、約24分の素材だった。AVFoundationは時間と映像トラックを読めるが `isPlayable=false`。従来のロード処理は時間と映像トラックの存在だけで成功扱いし、既存のプロキシ生成へフォールバックしなかった。

## 変更

- `loadPlayableAsset`でAVFoundationの実際の `isPlayable` を確認する。falseまたは読み込み失敗なら既存のプレビュー変換へ進む。拡張子やVP9だけの固定リストでは判定しない。
- 変換後のキャッシュも再生可否を確認し、失敗時は再帰変換せずエラーにする。
- 初回はH.264 VideoToolbox＋AACのプレビューをキャッシュに生成。時間が取得できた素材は進捗の分母に利用し、原本を変更しない旨を表示する。
- 原本URLを編集・書き出し・プロジェクト保存に保持し、プレビューキャッシュを原本へ置き換えない。
- 互換プレビュー使用時、書き出しパネルで「標準プレーヤー向けにはフレーム正確」を案内する。高速モードは元の映像コーデックをコピーするため、出力の再生互換性まで改善するとは限らない。
- ビルド時は実行ファイルを一時ファイル経由で置換し、稼働中の旧プロセスが参照する実行ファイルを直接切り詰めない。新ビルドの適用にはアプリの再起動が必要。

## 確認と限界

- ユーザー素材：原本 `isPlayable=false`、時間1454.341秒、映像トラック1を確認。60秒地点から3秒を同じプレビュー用エンコード条件で変換し、H.264／AAC、AVFoundation `isPlayable=true`、時間3.009秒を確認。原本は読み取りのみ。
- ビルド、TrimletCoreChecks、共有契約チェック成功。
- 回帰スクリプト `scripts/check-playback-compatibility.swift` は公開可能な合成VP9／Opus素材を生成して検証する。ユーザーの動画やパスをリポジトリへ追加しない。
- 回帰スクリプト実行結果はPASS。合成原本はduration/video trackあり・isPlayable=false、H.264/AACプレビューと切り出し出力はisPlayable=true、切り出し出力1.521秒。合成原本SHA-256が不変であることも確認した。実行方法：`swiftc -parse-as-library scripts/check-playback-compatibility.swift -o /tmp/trimlet-playback-check && /tmp/trimlet-playback-check`。
- UI操作接続がタイムアウトしたため、修正版アプリでの実際のドロップ→全長プロキシ生成→再生の一連確認は未完了。短区間検証を全24分のデコード保証とは扱わない。開いていた未保存状態はGit対象外の `TestMedia/compatibility-review-20260909.trimlet` に保存済み。
- AV1など別コーデック、破損素材、DRM保護素材すべてに対応したという意味ではない。今回ダウンロード機能やVLC組み込みは追加していない。

## Windows担当へ

OSのネイティブ再生対応と、コンテナのメタデータ読み取り成功を分けること。非対応時は互換プレビューを生成しても、編集・書き出しは原本を使用する。高速コピーとH.264再エンコードの出力互換性の違いもUIで説明する。共有プロジェクトスキーマの変更はない。
