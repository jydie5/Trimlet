# Windows → Mac: project persistence and build 10 interaction

Date: 2026-09-09. Based on Mac commit `3c7befd`. Development source only;
this is not a binary release or a new human-acceptance result.

Follow-up: the owner subsequently requested an unsigned Windows binary beta.
See [Beta download and limitations](BETA_DOWNLOAD.md) and
[binary publication verification](BETA_RELEASE_VERIFICATION.md) for `v0.4.0-beta.1`.
The original parity-check results below are historical and do not imply expanded human acceptance.

## Implemented

- Shared `.trimlet` version 1, closed JSON with required fields and 8 MiB limits,
  unique IDs, non-overlap and source-duration validation; all shared fixtures.
- Native Open Project, Save (`Ctrl+S`), Save As, drop and command-line project
  opening. Relative source references; missing-source relink, changed-source
  confirmation (size and modification time, with two-second precision tolerance).
- Same-directory temporary save, flushed before atomic replacement. Failed
  encoding/replacement preserves the existing project. Cross-drive paths are
  rejected with guidance to save on the video's drive.
- Dirty state for committed edits/name/order, mode, audio, relink and fallback;
  Save/Don't Save/Cancel before replacement or exit. Save is unavailable during
  loading, export and proxy generation. Source is probed and ranges validated
  before replacing edits; restoration waits for playable media; thumbnails follow.
- Original timestamp integer pairs survive restoration and unchanged trim ends.
  Optional original names/audio metadata survive unchanged saves.
- Upper ruler/playhead and lower range lane; exclusive 24-DIP outward grips;
  pointer-down capture/latching; translation from original boundary; zero-drag
  preview without snapping; release finalization; capture-loss rollback.
- Body/empty-space drags and wheel input only seek. Paused I/O works; IN keeps a
  later OUT or clears an invalid OUT; OUT at/before IN gives an inline error.
- Zoom, pan, full-source fit, range fit, source/sequence clocks and target/time
  feedback. Existing trim stays a draft until Apply (one Undo unit). Another
  trim, reorder, delete or Undo cannot silently discard the trim draft.
- Windows VFR timestamp stepping and validated preview proxies are retained.
  Fast candidate overlays appear in Fast mode; Accurate uses selected ranges.

## Verification

- Windows solution: 35 tests passed, including all 12 shared project fixtures,
  strict fields/size rejection, rational timestamp round-trip, atomic failure
  preservation, Unicode/relative paths, identity, range bounds, hit intervals,
  translation and zoom.
- Native Debug and Release builds passed. Shared validation: 2 export fixtures, 2 edit-list
  fixtures, 12 project fixtures and 9 error codes passed.
- Generated-media integration passed: Fast/Accurate, reordered multi-range
  colors and non-default audio, VFR navigation, M2TS/AC-3 proxy/cache reuse,
  safe paths and output finalization.
- Live developer UI: paused IN → upper-lane seek → OUT kept IN; IN drag changed
  only IN; padded OUT click preserved its boundary; Add changed purple to blue;
  zoom retained endpoints; three-clip project restored names/order/ranges/mode;
  Ctrl+S preserved 60000-timescale timestamps; mode change became dirty and
  closing showed Save/Don't Save/Cancel; Save then closed successfully.
- Startup verification exposed constructor-time loading failures. Command-line
  opening now runs after window activation; icon lookup uses the application
  directory and the launch profile is explicitly unpackaged. Repeated project
  launches after this change restored the three clips. Native Open Project was
  also exercised. Exception diagnostics omit messages containing media paths.
- The introduction image captures the running Windows app with original footage
  generated by `scripts/create-windows-demo.ps1`. No third-party footage/music,
  new dependencies or license changes; no source videos are committed.

## Return to the Mac maintainer

Please open a Windows-saved `.trimlet` on Mac with the same source and check
names, UUIDs, order, audio, mode and rational endpoints. Windows consumes the
shared fixtures; direct cross-machine UI round-trip is not yet verified.

Keep acceptance records separate. The 2026-08-28 Windows human acceptance does
not cover these additions. Physical precision-touchpad gestures, one-frame grips
at source edges, DPI/theme matrix, forced capture loss, missing/changed-source
dialog branches and audio fallback need the expanded Windows human check.
Broad damaged/HDR/interlaced/large-media and cancellation coverage, packaging,
clean-machine verification, signing and artwork remain release work.

No schema, export contract, source mutation policy or Mac native code changed.

remain in a detailed section with their provenance.
